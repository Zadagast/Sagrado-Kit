# AGENTS.md

## Cursor Cloud specific instructions

SagradoKit is a native **Win32 C++17** appearance kit. It is cross-compiled from
Linux with **MinGW-w64 (i686)** and run under **Wine**. It is not a
web/Electron/npm/pip project — there is no JS/Python package manager step for the
app itself (Python is only used to generate the optional emoji pack).

### Kit first (required)

Anything reusable belongs in the Kit (`engine/`), not in an app. Before writing
UI, layout, text, list, scroll, input, or drawing code inside `apps/` or
`editor/`, check whether `engine/` already provides it — and if it does not, add
it there and have the app call it. Apps hold only their own domain logic (XMPP
for Jabber, document state for TextEdit, skin authoring for the Editor).

This applies to fixes too: when a bug or performance problem is in shared
behaviour (painting, clipping, row maths, hit-testing, fonts, scrollbars), fix it
in `engine/` so every app benefits, rather than patching one app's copy. Cover
new Kit code with a host-native test wired into `make smoke`.

### Services / apps

Three Win32 GUI apps are produced under `build/` by the top-level `Makefile`:

- `build/SagradoKitEditor.exe` — the SagradoKit appearance/skin editor.
- `build/SagradoTextEdit.exe` — reference Sagrado App (plain-text editor).
- `build/SagradoJabber.exe` — AIM-era XMPP instant messenger.

### Build / test / run

Standard commands live in the `Makefile` and `README.md`; use those rather than
hand-rolling compiler invocations:

- Build everything: `make` (Editor + TextEdit + Jabber + example skins).
- Host-native tests (no Wine, plain `g++`): `make smoke`.
- Run an app: `make run` / `make run-textedit` / `make run-jabber`.

### Non-obvious gotchas

- The `run*` targets prefer `wine64`, then fall back to `wine`. `wine64` is not
  installed in this environment, so `wine` (32-bit) is used — that is correct
  for the i686 binaries, so the fallback path is expected, not an error.
- GUI apps need a display. Use whichever desktop the environment already runs —
  a TigerVNC session is usually `DISPLAY=:1`, while hosted agent desktops expose
  `DISPLAY=:0`; check with `xdotool getdisplaygeometry` before assuming. To
  launch outside `make`, run e.g.
  `DISPLAY=:0 WINEDEBUG=-all wine build/SagradoTextEdit.exe`. `WINEDEBUG=-all`
  silences noisy Wine fixme logs.
- The Wine prefix (`~/.wine`) is created on first `wineboot`/run. If it is
  missing, run `wineboot --init` once before launching apps.
- The apps are borderless `WS_POPUP` gel windows (no OS title bar). Move a
  window by dragging its painted gel header, not an OS caption.
- Emoji pack: the Jabber Emoji Picker uses an on-disk pack at
  `build/emoji_pack/` generated by `tools/gen_emoji_pack.py` (needs Python
  Pillow + the `NotoColorEmoji.ttf` font). The Jabber build target only
  regenerates it when `build/emoji_pack/catalog.txt` is **absent**. So after a
  `make clean` (or if you delete `build/`) followed by an incremental rebuild
  where Jabber is already up to date, the pack may not be regenerated — run
  `make emoji-pack` explicitly if the picker is empty.
- Jabber needs live network (XMPP + HTTP upload) to actually sign on; offline it
  still launches and paints the buddy-list UI.
